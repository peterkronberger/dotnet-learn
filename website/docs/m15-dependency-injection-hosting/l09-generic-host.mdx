## Ein Host für alles

In den letzten Lektionen hast du drei Dinge einzeln aufgebaut: den Container mit `ServiceCollection` (`m15-l02`), das Logging (`m15-l05`) und die Konfiguration (`m15-l07`). Der <Term id="generic-host">Generic Host</Term> fasst sie in einem Objekt zusammen. Er ist außerdem für den Start und das geordnete Beenden der Anwendung zuständig ([.NET Generic Host](https://learn.microsoft.com/dotnet/core/extensions/generic-host)).

Der Host ist im Paket `Microsoft.Extensions.Hosting`. Du baust ihn in vier Schritten:

1. **Builder erzeugen:** `Host.CreateApplicationBuilder(args)` gibt einen `HostApplicationBuilder` zurück. Die `args` sind die Argumente der Kommandozeile.
2. **Einstellen:** Der Builder hat die Eigenschaften `Services` (die `IServiceCollection`), `Logging`, `Configuration` und `Environment`. Du registrierst Services, Logging-Provider und Konfigurationsquellen direkt auf ihm.
3. **Bauen:** `Build()` erzeugt den Host (`IHost`). Dabei entsteht auch der Service-Provider.
4. **Laufen lassen:** `RunAsync()` startet den Host und gibt erst zurück, wenn er stoppt.

Schon ohne weitere Angaben richtet der Builder einiges ein:

- **Konfiguration** aus `appsettings.json`, `appsettings.{Environment}.json`, den Umgebungsvariablen und der Kommandozeile (`m15-l07`). In der Umgebung `Development` kommt der Secret Manager dazu.
- **Logging-Provider:** Console, Debug und EventSource, unter Windows auch EventLog (`m15-l05`).
- **Prüfung der Lebensdauern** (`m15-l04`): In der Umgebung `Development` sind `ValidateScopes` und `ValidateOnBuild` eingeschaltet.
- **Eigene Services:** `IHostApplicationLifetime`, `IHostLifetime` und `IHostEnvironment` sind automatisch registriert.

Das Stammverzeichnis, aus dem der Host Dateien wie `appsettings.json` liest, ist standardmäßig das aktuelle Arbeitsverzeichnis ([Generic Host: Host builder settings](https://learn.microsoft.com/dotnet/core/extensions/generic-host#host-builder-settings)).

## Dienste im Host

Eine Anwendung auf dem Host tut ihre Arbeit in gehosteten Diensten. Ein <Term id="hosted-service">Hosted Service</Term> ist eine Klasse, die `IHostedService` implementiert. Das Interface hat zwei Methoden: `StartAsync` und `StopAsync`. Der Host ruft `StartAsync` aller registrierten Dienste beim Start und `StopAsync` beim Beenden auf ([Worker Services in .NET](https://learn.microsoft.com/dotnet/core/extensions/workers)).

Meist schreibst du den Dienst nicht von Hand. `BackgroundService` ist eine abstrakte Klasse, die `IHostedService` implementiert. Deine Unterklasse überschreibt eine einzige Methode:

```csharp
protected override Task ExecuteAsync(CancellationToken stoppingToken)
```

Die Methode gibt einen `Task` zurück, der die Dauer der langlaufenden Arbeit darstellt. Der `stoppingToken` ist ein `CancellationToken` (`m13-l05`), den der Host abbricht, wenn er stoppt, also wenn `StopAsync` aufgerufen wird.

Ein typischer Dienst läuft in einer Schleife, bis der Token abgebrochen wird. Wie in `m13-l05` ist der Abbruch kooperativ: Der Token muss in der Schleife geprüft und an `Task.Delay` weitergegeben werden.

Die Vorlage `dotnet new worker` erzeugt genau dieses Gerüst: ein `Program` mit Host und eine Klasse `Worker`.

Die Schritte:

1. **Bauen:** `Build()` erzeugt den Host. Noch läuft kein Dienst. Die Zeile „host built“ kommt zuerst.
2. **Starten:** `RunAsync()` ruft `StartAsync` des Dienstes auf. Die Methode der Basisklasse startet `ExecuteAsync`.
3. **Arbeiten:** `ExecuteAsync` zählt drei Schritte. Jeder wartet kurz mit `Task.Delay`, und der Token wird weitergegeben.
4. **Stoppen anfordern:** Nach Schritt 3 ruft der Dienst `StopApplication()` auf. Das ist das Signal an den Host, zu stoppen.
5. **Stoppen:** Der Host ruft `StopAsync` des Dienstes auf. Danach gibt `RunAsync` zurück, und `Main` druckt „host stopped“.

**Was passiert, wenn …** du die Zeile mit `StopApplication()` löschst? Dann endet `ExecuteAsync` nach Schritt 3, aber der Host läuft weiter, bis du ihn stoppst, zum Beispiel mit Strg+C. Ein Dienst, der fertig ist, beendet den Host nicht von selbst ([Worker Services: Signal completion](https://learn.microsoft.com/dotnet/core/extensions/workers#signal-completion)).

</details>

### Das Beenden mit Strg+C

Im Betrieb endet ein Host meist nicht durch den Dienst selbst, sondern durch ein Signal von außen: Strg+C in der Konsole oder `docker stop`. Der Host reagiert darauf geordnet. Dieses <Term id="graceful-shutdown">geordnete Beenden</Term> läuft so ab:

1. `ApplicationStopping` wird ausgelöst. Der `stoppingToken` der Dienste wird abgebrochen.
2. Der Host ruft `StopAsync` der Dienste auf.
3. `ApplicationStopped` wird ausgelöst, und `RunAsync` gibt zurück.

`ApplicationStopping` und `ApplicationStopped` sind Eigenschaften von `IHostApplicationLifetime`. Auch `StopApplication()` ist dort. Du kannst den Dienst also auch von außen bitten zu stoppen, zum Beispiel mit einem Dienst, der fertig ist. Die Zeit, die `StopAsync` hat, ist begrenzt. Sie heißt `HostOptions.ShutdownTimeout` und lässt sich einstellen ([Generic Host: Host shutdown](https://learn.microsoft.com/dotnet/core/extensions/generic-host#host-shutdown)). Ein Dienst, der nicht auf den Token reagiert, hält das Beenden also auf, bis diese Zeit abgelaufen ist.

## Wenn der Dienst scheitert

Was passiert, wenn `ExecuteAsync` eine Ausnahme wirft, die niemand fängt? Der Host meldet die Ausnahme und stoppt. Das Verhalten steht in `HostOptions.BackgroundServiceExceptionBehavior`: Der Standard ist `StopHost`, mit `Ignore` läuft der Host weiter ([Exception handling in hosting](https://learn.microsoft.com/dotnet/core/compatibility/core-libraries/6.0/hosting-exception-handling)).

## Achtung

:::warning[Achtung]
<Misconception id="m15-l09-exception-keeps-host-running" />

**„Eine Ausnahme in `ExecuteAsync` geht verloren, und der Host läuft weiter.“** Der Host meldet die Ausnahme und stoppt, das ist der Standard `StopHost`. Nur mit `BackgroundServiceExceptionBehavior.Ignore` bleibt der Host am Laufen.
:::

## Zusammenfassung

Der Generic Host fasst Dependency Injection, Logging und Konfiguration zusammen. `Host.CreateApplicationBuilder` richtet Standardquellen und -provider ein, `Build()` erzeugt den Host und `RunAsync()` lässt ihn laufen. Gehostete Dienste implementieren `IHostedService`, ein `BackgroundService` schreibt nur `ExecuteAsync` und reagiert auf den `stoppingToken`. Beim Beenden löst der Host `ApplicationStopping` aus, ruft `StopAsync` der Dienste auf und löst `ApplicationStopped` aus. Eine unbehandelte Ausnahme in `ExecuteAsync` stoppt den Host, und `StopApplication()` beendet ihn von innen.
