# Exceptions abfangen mit try und catch

:::note[Lernziele]
- Du kannst erklären, was beim Auslösen einer Exception mit dem restlichen Code passiert.
- Du kannst eine Anweisung, die fehlschlagen kann, mit `try`/`catch` absichern und `Message` der Exception ausgeben.
- Du kannst häufige Exception-Typen den Fehlern zuordnen, die sie auslösen.
:::

:::tip[Projekt: Was SecLog nach diesem Modul kann]
- SecLog fängt Fehler beim Verarbeiten von Log-Zeilen ab, statt abzustürzen.
- SecLog weist ungültige Log-Zeilen mit einer eigenen Exception zurück.
- SecLog liest das Log aus einer Datei und gibt die Datei danach sauber wieder frei.
:::

## Wenn eine Anweisung fehlschlägt

Bisher hast du Fehler zur Laufzeit gesehen, zum Beispiel bei `int.Parse` mit einem Text, der keine Zahl ist. Hinter solchen Fehlern steckt ein Mechanismus: Wenn eine Operation nicht gelingt, <Term id="throw-exception">löst</Term> das Programm eine <Term id="exception">Exception (Ausnahme)</Term> aus ([§22.2 Causes of exceptions](https://learn.microsoft.com/dotnet/csharp/language-reference/language-specification/exceptions#222-causes-of-exceptions)). Eine Exception ist ein Objekt, das den Fehler beschreibt. Ihre Eigenschaft `Message` enthält eine lesbare Beschreibung ([§22.3 The System.Exception class](https://learn.microsoft.com/dotnet/csharp/language-reference/language-specification/exceptions#223-the-systemexception-class)).

Sobald eine Exception ausgelöst ist, läuft die nächste Anweisung nicht mehr. Das Programm sucht stattdessen jemanden, der die Exception behandelt. Findet es niemanden, endet das Programm mit einer Fehlermeldung. Du kannst die Behandlung selbst schreiben, mit einer <Term id="try-statement">`try`-Anweisung</Term>:

- Der `try`-Block enthält die Anweisungen, die fehlschlagen können.
- Eine <Term id="catch-clause">`catch`-Klausel</Term> sagt, welchen <Term id="exception-type">Exception-Typ</Term> sie behandelt, und gibt der Exception einen Namen. Ihr Block läuft nur, wenn der `try`-Block eine passende Exception auslöst.

:::info[Vorhersage]
Was gibt das Programm aus? Notiere deinen Tipp für jede Zeile. Achte besonders darauf, ob die Zeile `Number: …` erscheint.
:::

<details>
<summary>Lösung und Erklärung anzeigen</summary>

Die Ausgabe hat drei Zeilen: `Before the try block`, die Beschreibung der Exception und `After the try statement`. Die Zeile `Number: …` fehlt.

1. **Ausführen:** `int.Parse("seven")` kann den Text nicht lesen und löst eine `FormatException` aus.
2. **Abbrechen:** Der Rest des `try`-Blocks wird übersprungen. Deshalb gibt es kein `Number: …`.
3. **Fangen:** Der Typ `FormatException` passt zur `catch`-Klausel. `ex` ist die Exception, `ex.Message` ihre Beschreibung.
4. **Weitermachen:** Nach der `catch`-Klausel läuft das Programm hinter der ganzen `try`-Anweisung weiter ([§13.11 The try statement](https://learn.microsoft.com/dotnet/csharp/language-reference/language-specification/statements#1311-the-try-statement)).

Was passiert, wenn du `"seven"` durch `"7"` ersetzt? Dann löst nichts eine Exception aus. Der `try`-Block läuft ganz durch, und die `catch`-Klausel wird übersprungen.

</details>

## Welche Fehler gibt es?

Jede Exception hat einen Typ, und der Typ sagt, was schiefging. Die `catch`-Klausel nennt den Typ, den sie fängt. Eine Klausel für `FormatException` fängt also keine `DivideByZeroException`. Die C#-Spezifikation nennt dafür einige häufige Typen ([§22.5 Common exception classes](https://learn.microsoft.com/dotnet/csharp/language-reference/language-specification/exceptions#225-common-exception-classes)). Das Beispiel löst fünf davon nacheinander aus und fängt jede in einem eigenen `try`.

<CSharpRunner id="m07-l01-types" code={exceptionTypes} />

| Exception-Typ | Auslöser | Bekannt aus |
| --- | --- | --- |
| `DivideByZeroException` | Ganzzahldivision durch 0 | Modul 1 |
| `IndexOutOfRangeException` | Index außerhalb eines Arrays | Modul 5 |
| `InvalidCastException` | Umwandlung eines `object` in den falschen Typ | Modul 4 |
| `NullReferenceException` | Zugriff auf ein Mitglied von `null` | Modul 4 |
| `OverflowException` | Überlauf in einem `checked`-Kontext | Modul 1, Lektion 7 |
| `FormatException` | Text hat nicht die erwartete Form, etwa bei `int.Parse` | Modul 1, Lektion 8 |
| `InvalidOperationException` | `.Value` eines `int?` ohne Wert | Modul 4 |
| `KeyNotFoundException` | Schlüssel fehlt im `Dictionary` | Modul 5 |

`FormatException` und `KeyNotFoundException` stehen in der Bibliothek von .NET, nicht in der Liste der Spezifikation. Im Beispiel ist `names` ein neues Array mit einem Element, und ein Element eines Textarrays ist anfangs `null`. Die Meldungen stammen aus einem echten Lauf.

2. **Fangen:** `catch (FormatException) { Console.WriteLine($"Not a number: {text}"); }` behandelt den Fehlerfall.

## Achtung

:::warning[Achtung]
<Misconception id="m07-l01-resume-after-error" />

**„Nach dem `catch` macht das Programm mit der Zeile nach der fehlerhaften Anweisung weiter.“** Das stimmt nicht. Der Rest des `try`-Blocks wird übersprungen, und das Programm macht hinter der ganzen `try`-Anweisung weiter. Eine Anweisung, die nach der fehlerhaften im `try`-Block steht, läuft nie, auch nicht nach dem `catch`.
:::

<details>
<summary>Vertiefung: Wann ist ein Fehler eine Exception? (optional)</summary>

Die Spezifikation nennt zwei Ursachen für Exceptions: die Anweisung `throw` und Operationen, die nicht gelingen ([§22.2 Causes of exceptions](https://learn.microsoft.com/dotnet/csharp/language-reference/language-specification/exceptions#222-causes-of-exceptions)). `throw` lernst du in Lektion 5. Nicht jeder Fehler braucht eine Exception: `int.TryParse` meldet einen ungültigen Text über seinen Rückgabewert. Wann welcher Weg passt, vergleicht Lektion 7.

Ein `try`-Block ohne Exception läuft bis zum Ende. Dann springt das Programm zum Ende der `try`-Anweisung, ohne eine `catch`-Klausel auszuführen ([§13.11 The try statement](https://learn.microsoft.com/dotnet/csharp/language-reference/language-specification/statements#1311-the-try-statement)).

</details>

## Zusammenfassung

Eine Operation, die nicht gelingt, löst eine Exception aus. Der restliche Code im selben Ablauf läuft dann nicht mehr, bis jemand die Exception behandelt. Mit `try` sicherst du Anweisungen ab, eine `catch`-Klausel fängt eine Exception ihres Typs. Der Rest des `try`-Blocks wird übersprungen, und das Programm macht hinter der `try`-Anweisung weiter. `ex.Message` beschreibt den Fehler. Der Typ der Exception, etwa `FormatException` oder `DivideByZeroException`, sagt, was schiefging.
