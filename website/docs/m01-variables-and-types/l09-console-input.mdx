## Eine Zeile einlesen

Bisher stand jeder Wert fest im Programmtext. Echte Programme bekommen ihre Werte oft von außen, zum Beispiel vom Nutzer. Die <Term id="console-input">Konsoleneingabe (Console Input)</Term> liest Text, den der Nutzer in der Konsole tippt. `Console.ReadLine()` liest eine Zeile bis zum Zeilenumbruch und liefert sie ohne den Zeilenumbruch zurück ([Console.ReadLine](https://learn.microsoft.com/dotnet/api/system.console.readline)). Das Ergebnis speicherst du in einer Variable, hier mit `var`.

In einem Konsolenfenster hält das Programm bei `Console.ReadLine()` an und wartet auf deine Eingabe. Im Runner dieser Seite steht die Eingabe schon vor dem Start fest: Sie steht im Feld „Eingabe (Konsole)“ unter dem Editor. Jede Zeile dort liest ein Aufruf von `Console.ReadLine()`.

:::info[Vorhersage]
Das Feld enthält die Zeile `alice`. Welche zwei Zeilen gibt das Programm aus?
:::

<CSharpRunner id="m01-l09-echo" code={readlineEcho} stdin={readlineEchoInput} predict expected={readlineEchoOutput} />

<details>
<summary>Lösung und Erklärung anzeigen</summary>

Die Ausgabe sind zwei Zeilen: `Hello, alice!` und `alice`.

1. **Zeile lesen:** `Console.ReadLine()` liefert den Text `alice`. Er steht jetzt in `name`.
2. **Text verwenden:** Die Interpolation setzt `name` in den Satz ein. Die zweite Ausgabe gibt `name` allein aus.

Was passiert, wenn du im Feld eine andere Zeile einträgst, zum Beispiel `bob`? Ändere das Feld und führe das Programm erneut aus.

</details>

## Mehrere Zeilen: Jeder Aufruf liest die nächste

Ein Aufruf liest genau eine Zeile. Liest ein Programm mehrere Zeilen, liest der erste Aufruf die erste Zeile, der zweite Aufruf die zweite und so weiter. Eine Zeile, die kein Aufruf liest, bleibt ungelesen.

:::info[Vorhersage]
Das Feld enthält drei Zeilen: `login-failed`, `bob` und `203.0.113.7`. Welche zwei Zeilen gibt das Programm aus?
:::

<CSharpRunner id="m01-l09-lines" code={readlineLines} stdin={readlineLinesInput} predict expected={readlineLinesOutput} />

<details>
<summary>Lösung und Erklärung anzeigen</summary>

Die Ausgabe sind zwei Zeilen: `Second read: bob` und `First read: login-failed`.

1. **Erster Aufruf:** `first` bekommt die erste Zeile, `login-failed`.
2. **Zweiter Aufruf:** `second` bekommt die nächste Zeile, `bob`.
3. **Ausgabe:** Die Ausgabe nennt die Variablen in umgekehrter Reihenfolge. Die Reihenfolge der Eingabe ändert das nicht.

Die dritte Zeile, `203.0.113.7`, liest kein Aufruf. Sie bleibt ungelesen.

</details>

:::warning[Achtung]
<Misconception id="m01-l09-readline-reads-all" />

**„Ein `Console.ReadLine()` liest die ganze Eingabe.“** Ein Aufruf liest nur eine Zeile. Für drei Zeilen brauchst du drei Aufrufe.
:::

## Die Eingabe ist immer Text

Auch wenn du `42` eintippst, liefert `Console.ReadLine()` den Text `"42"`: die Zeichen `4` und `2`. Das Programm kann nicht wissen, ob du eine Zahl, ein Wort oder einen Namen meinst. Zum Rechnen brauchst du eine Zahl. Dafür wandelst du den Text mit dem Parsen aus der letzten Lektion um. `int.TryParse` nimmt den eingelesenen Text als erstes Argument an ([Int32.TryParse](https://learn.microsoft.com/dotnet/api/system.int32.tryparse)).

<Forward concepts={['`out`-Parameter']} module="3" />

:::info[Vorhersage]
Das Feld enthält die Zeile `42`. Welche drei Zeilen gibt das Programm aus? Vergleiche die erste und die dritte Zeile.
:::

<CSharpRunner id="m01-l09-number" code={readlineNumber} stdin={readlineNumberInput} predict expected={readlineNumberOutput} />

<details>
<summary>Lösung und Erklärung anzeigen</summary>

Die Ausgabe sind drei Zeilen: `421`, `True` und `43`.

1. **Zeile lesen:** `text` ist der Text `"42"`.
2. **Text verketten:** `text + 1` hängt das Zeichen `1` an: `421`.
3. **Umwandeln und rechnen:** `int.TryParse` liefert `True` und die Zahl `42` in `number`. Dann gilt `number + 1`: `43`.

</details>

:::warning[Achtung]
<Misconception id="m01-l09-readline-returns-number" />

**„Tippe ich `42`, liefert `Console.ReadLine()` die Zahl 42.“** Das Ergebnis ist immer Text. Erst `int.Parse` oder `int.TryParse` macht daraus eine Zahl. Ohne Umwandlung verkettet `+` den Text, und aus `42` plus `1` wird `421`.
:::

## Lückenbeispiel

Dasselbe Vorgehen mit Lücken: Die Schrittbezeichnungen in den Kommentaren bleiben. Das Feld enthält `12`, `2.5` und `twelve`. Ersetze in den drei Zeilen mit `0` und `true` den Wert so, dass die Ausgabe `24`, `5` und `False` lautet. Verwende die Rezepte `int.TryParse(countText, out int count);`, `double.TryParse(rateText, out double rate);` und `bool worked = int.TryParse(thirdText, out int ignored);`.

<CSharpRunner id="m01-l09-gaps" code={readlineGaps} stdin={readlineGapsInput} />

<details>
<summary>Lösung anzeigen</summary>

1. **Ganze Zahl:** `int.TryParse(countText, out int count);` ergibt `12`, mal zwei `24`.
2. **Dezimalzahl:** `double.TryParse(rateText, out double rate);` ergibt `2.5`, mal zwei `5`.
3. **Prüfen:** `bool worked = int.TryParse(thirdText, out int ignored);` ergibt `False`, weil ein Wort keine Zahl ist.

</details>

## Zusammenfassung

`Console.ReadLine()` liest eine Zeile Eingabe ohne Zeilenumbruch. Mehrere Zeilen brauchen mehrere Aufrufe, jeder liest die nächste Zeile. Das Ergebnis ist immer Text, auch bei `42`. Zum Rechnen wandelst du den Text mit `int.Parse` oder `int.TryParse` um. Im Runner steht die Eingabe vor dem Start im Feld, im Konsolenfenster wartet das Programm auf dich.
