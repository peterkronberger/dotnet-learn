## Eine Abfrage wird zu einer SQL-Anweisung

Eine LINQ-Abfrage auf einem `DbSet` läuft nicht in C#. EF Core liest den Aufbau der Abfrage und erzeugt daraus eine einzige SQL-Anweisung, die die Datenbank ausführt ([How queries work](https://learn.microsoft.com/ef/core/querying/how-query-works)). Das ist die <Term id="query-translation">Abfrageübersetzung</Term>. Die Lambdas wie `i => i.FailureCount >= 5` werden dabei nicht aufgerufen, sondern gelesen und übersetzt.

`ToQueryString()` zeigt dir das SQL, ohne die Abfrage auszuführen. Das folgende Programm schreibt dieselbe Abfrage zweimal: in Methoden-Syntax und in Abfrage-Syntax.

Das SQL hat eine feste Reihenfolge von Teilen. Jedes Schlüsselwort entspricht einem LINQ-Operator:

1. **`SELECT`:** Die Spaltenliste. Sie kommt aus `Select`. Nur `User` und `FailureCount` stehen darin, weil nur diese gebraucht werden.
2. **`FROM`:** Die Tabelle, aus der gelesen wird: `Incidents`. `AS "i"` gibt ihr den Kurznamen `i`, wie die Lambda-Variable.
3. **`WHERE`:** Die Bedingung aus `Where`.
4. **`ORDER BY`:** Die Sortierung aus `OrderByDescending`. `DESC` heißt absteigend.
5. **`LIMIT`:** Die Höchstzahl der Zeilen aus `Take`.

Bei `Take(1)` steht der Wert nicht im Text, sondern als Parameter: `.param set @p 1` legt den Wert fest, und `@p` im SQL ist der Platzhalter dafür. Ein Parameter ist ein Platzhalter, den die Datenbank beim Ausführen mit dem Wert füllt. So steht ein Wert aus deinem Programm nie als Text im SQL.

`Same SQL: True` zeigt: Beide Schreibweisen ergeben dieselbe Anweisung.

**Was passiert, wenn …** du `OrderByDescending` durch `OrderBy` ersetzt? Dann steht `ORDER BY "i"."FailureCount"` ohne `DESC` im SQL.

</details>

## Abfrage-Syntax wird zuerst zu Methodenaufrufen

Die Abfrage-Syntax (`from … where … select`) kennt EF Core nicht selbst. Der Compiler übersetzt sie zuerst in Methodenaufrufe. Auf einer Quelle vom Typ `IQueryable<T>`, wie sie ein `DbSet` ist, sind das die Methoden der Klasse `Queryable`: `where` wird zu `Queryable.Where`, `select` zu `Queryable.Select` ([Query expression translation (§12.20.3)](https://learn.microsoft.com/dotnet/csharp/language-reference/language-specification/expressions#12203-query-expression-translation)). Erst diese Aufrufe übersetzt EF Core in SQL. Darum ist das Ergebnis oben gleich.

## Wann läuft die Abfrage?

Wie bei LINQ auf Listen (verzögerte Ausführung, `m11-l05`) tut das Schreiben der Abfrage nichts. Die Abfrage geht an die Datenbank, wenn du sie ausliest: mit `foreach`, `ToList()` oder `First()`. Aggregate wie `Count` und `Any` laufen sofort und in der Datenbank ([Querying data](https://learn.microsoft.com/ef/core/querying/)).

## Achtung

:::warning[Achtung]
<Misconception id="m16-l04-query-loads-whole-table" />

**„EF Core lädt erst die ganze Tabelle und filtert dann in C#.“** `Where`, `OrderBy` und `Select` werden in SQL übersetzt, und die Datenbank liefert nur die passenden Zeilen und Spalten. Das gilt für Code, den EF Core übersetzen kann. Was es nicht übersetzen kann, folgt in einer späteren Lektion.
:::

## Zusammenfassung

EF Core übersetzt eine LINQ-Abfrage auf einem `DbSet` in eine SQL-Anweisung: `Where` wird zu `WHERE`, `OrderBy` zu `ORDER BY`, `Select` zur Spaltenliste, `Take` zu `LIMIT`. Die Abfrage-Syntax wird vom Compiler zuerst in `Queryable`-Aufrufe umgeschrieben. Das Schreiben der Abfrage sendet nichts, erst das Auslesen (`foreach`, `ToList`, `First`) und Aggregate wie `Count` und `Any`. `ToQueryString()` zeigt das SQL, ohne es auszuführen.
