## Daten, die den Neustart überleben

Bisher lebten alle Daten von SecLog im Speicher: Wenn das Programm endet, sind die Vorfälle weg. Eine <Term id="relational-database">relationale Datenbank</Term> speichert Daten dauerhaft. Sie ordnet sie in Tabellen an. Eine <Term id="database-table">Tabelle</Term> besteht aus:

- **Spalten:** Jede Spalte hat einen Namen und einen Typ, zum Beispiel `User` (Text) und `FailureCount` (Ganzzahl).
- **Zeilen:** Jede Zeile ist ein einzelner Eintrag, hier ein Vorfall. Sie hat für jede Spalte einen Wert.

| Id | User | FailureCount |
| --- | --- | --- |
| 1 | bob | 5 |
| 2 | dave | 1 |

Damit man jede Zeile eindeutig ansprechen kann, hat die Tabelle einen <Term id="primary-key">Primärschlüssel</Term>: eine Spalte, deren Wert in jeder Zeile anders ist. Hier ist es `Id`.

Mit einer Datenbank sprichst du in <Term id="sql">SQL</Term>. Das ist die Sprache der Datenbank, zum Beispiel `SELECT` zum Lesen und `INSERT` zum Anlegen einer Zeile. In dieser Lektion schreibst du kein SQL selbst. Du arbeitest mit C#-Objekten, und eine Bibliothek übersetzt sie in SQL.

## Entity Framework Core

<Term id="ef-core">Entity Framework Core</Term> ist ein <Term id="orm">O/RM</Term> (objektrelationaler Mapper): Es bildet Klassen auf Tabellen ab. Ein Objekt entspricht einer Zeile, eine Eigenschaft einer Spalte. Du schreibst C# und LINQ, EF Core erzeugt das SQL und baut aus den Zeilen wieder Objekte ([Overview of Entity Framework Core](https://learn.microsoft.com/ef/core/)).

EF Core kommt als NuGet-Paket (`m14-l02`). Welche Datenbank dahinter steckt, bestimmt ein <Term id="database-provider">Database Provider</Term>, ebenfalls ein Paket. Es gibt Provider zum Beispiel für SQL Server, PostgreSQL und SQLite. Dieses Modul benutzt SQLite: Die ganze Datenbank ist eine Datei, und es braucht keinen Server. Dafür verweist ein Projekt auf das Paket `Microsoft.EntityFrameworkCore.Sqlite`.

Die Datenbank findet das Programm über einen <Term id="connection-string">Connection String</Term>. Bei SQLite ist das der Dateiname: `Data Source=seclog.db`.

## Entity-Klasse und DbContext

Zwei Dinge beschreiben dein Modell:

1. Eine <Term id="entity-type">Entity-Klasse</Term> ist eine gewöhnliche Klasse mit Eigenschaften. Eine Eigenschaft `Id` ist der Primärschlüssel.
2. Ein <Term id="dbcontext">`DbContext`</Term> ist die Sitzung mit der Datenbank. Du schreibst eine Klasse, die von `DbContext` erbt. Für jede Tabelle hat sie eine <Term id="dbset">`DbSet<T>`</Term>-Eigenschaft.

Den Context bekommt seine Einstellungen als `DbContextOptions<T>` im Konstruktor. Die Optionen baust du mit `DbContextOptionsBuilder<T>`, und `UseSqlite(…)` wählt den Provider und gibt den Connection String an ([DbContext Lifetime, Configuration, and Initialization](https://learn.microsoft.com/ef/core/dbcontext-configuration/)).

Die Schritte im Programm:

1. **Datenbank bereitstellen:** `EnsureCreated()` legt die Datenbank mit den Tabellen für das Modell an, falls es sie noch nicht gibt. Das ist der einfache Start. Später ersetzen Migrationen diesen Weg (`m16-l08`).
2. **Objekte vormerken:** `Add` und `AddRange` melden dem Context neue Objekte. Es geschieht noch nichts in der Datenbank.
3. **Speichern:** `SaveChanges()` schickt die Befehle an die Datenbank. Die Datenbank vergibt den Schlüssel, und EF Core schreibt ihn ins Objekt zurück.
4. **Lesen:** Eine LINQ-Abfrage auf dem `DbSet` mit `Where` und `ToList()` holt die passenden Zeilen als Objekte.

## Das DbSet ist der Start einer Abfrage

Ein `DbSet<T>` sieht aus wie eine Liste, ist aber keine. Es hält keine Zeilen im Speicher. Es ist der Ausgangspunkt für Abfragen und für `Add`. Erst wenn eine Abfrage ausgelesen wird, liest EF Core Zeilen. Das kennst du von LINQ im Speicher: Die Abfrage läuft erst beim Auslesen (`m11-l05`).

## Achtung

:::warning[Achtung]
<Misconception id="m16-l01-dbset-holds-all-rows" />

**„Ein `DbSet<T>` ist eine Liste, die alle Zeilen der Tabelle im Speicher hält.“** Ein `DbSet<T>` ist der Start einer Abfrage. Zeilen kommen erst in den Speicher, wenn eine Abfrage ausgelesen wird, zum Beispiel mit `ToList()`. Das gilt auch für jede weitere Abfrage: Sie läuft bei jedem Auslesen neu in der Datenbank.
:::

## Zusammenfassung

Eine relationale Datenbank speichert Daten in Tabellen mit Spalten und Zeilen. Der Primärschlüssel kennzeichnet jede Zeile eindeutig. EF Core bildet Klassen auf Tabellen ab: Ein `DbContext` mit `DbSet<T>`-Eigenschaften beschreibt das Modell, ein Database Provider und ein Connection String legen die Datenbank fest. `Add` merkt Objekte vor, `SaveChanges` schreibt sie, und die Datenbank vergibt den Schlüssel. Eine LINQ-Abfrage auf dem `DbSet` läuft beim Auslesen in der Datenbank. Das `DbSet` selbst hält keine Zeilen.
