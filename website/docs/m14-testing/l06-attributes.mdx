## Zusatzinformation für Code

Ein <Term id="attribute">Attribut</Term> (attribute) ist eine Zusatzinformation, die du in eckigen Klammern vor eine Deklaration schreibst, zum Beispiel vor eine Methode. Du kennst schon zwei: `[Flags]` an einem Enum (Modul 8) und `[EnumeratorCancellation]` an einem Parameter einer asynchronen Iteratormethode (Modul 13). Dort stand nur, was sie bewirken. Jetzt siehst du, wie sie funktionieren.

Ein Attribut führt von sich aus keinen Code aus. Es beschreibt das Element, an dem es steht. Der Compiler wertet manche Attribute aus. Andere liest ein Werkzeug oder ein Framework zur Laufzeit. xUnit liest `[Fact]` (Lektion 7), ASP.NET Core und EF Core lesen ihre Attribute ebenfalls. Wie das Auslesen funktioniert, ist nicht Thema des Kurses.

## Attribute anwenden

Ein Attribut ist der Name einer <Term id="attribute-class">Attributklasse</Term> ohne das Suffix `Attribute`: `[Obsolete]` meint die Klasse `ObsoleteAttribute`. Die Argumente stehen in runden Klammern:

- **Positionsparameter** stehen zuerst und gehören zum Konstruktor: `[Author("Dana")]`.
- **Benannte Parameter** folgen mit `Name = Wert` und setzen eine öffentliche Eigenschaft: `[Author("Dana", Version = 2)]`.

Mehrere Attribute stehen untereinander oder getrennt durch Kommas in einer Klammer. Nur Werte, die der Compiler selbst kennt, sind erlaubt, zum Beispiel Zahlen, Texte und `true`.

Das <Term id="attribute-target">Attributziel</Term> (attribute target) ist das Element, auf das sich das Attribut bezieht. Meistens ergibt es sich aus der Stelle: Vor einer Methode meint es die Methode, vor einer Klasse die Klasse. Du kannst es mit einem Präfix nennen: `[return: …]` meint den Rückgabewert, `[assembly: …]` die ganze Assembly.

## Eine eigene Attributklasse

Eine Attributklasse erbt von `Attribute`. Ihr Konstruktor legt die Positionsparameter fest, öffentliche Eigenschaften mit `set` sind die benannten Parameter. Mit `[AttributeUsage]` legst du fest, wo das Attribut stehen darf (`AttributeTargets`) und ob es mehrfach erlaubt ist (`AllowMultiple`). Ohne `[AttributeUsage]` darf es überall stehen, aber nur einmal je Element.

## Conditional

<Term id="conditional-attribute">`[Conditional("SYMBOL")]`</Term> an einer Methode macht sie zu einer bedingten Methode (Symbole für bedingte Kompilierung kennst du aus Lektion 3). Der Compiler übernimmt einen Aufruf nur, wenn das Symbol **an der Aufrufstelle** definiert ist. Sonst entfällt der Aufruf samt seiner Argumente.

:::info[Vorhersage]
`TRACE_STEPS` ist definiert, `VERBOSE_STEPS` nicht. Was gibt das Programm aus, und wie oft läuft `Next()`?
:::

<CSharpRunner id="m14-l06-conditional" code={conditionalCalls} predict expected={conditionalCallsOutput} />

<details>
<summary>Lösung und Erklärung anzeigen</summary>

1. **Symbol prüfen:** `TRACE_STEPS` ist am Dateianfang definiert, der Aufruf von `Trace` bleibt. `Next()` läuft und gibt 1 zurück.
2. **Zweiten Aufruf prüfen:** `VERBOSE_STEPS` ist nicht definiert. Der Aufruf von `Verbose` entfällt mit dem Argument `Next()`. Die Methode läuft nicht.
3. **Ergebnis:** `Next()` lief genau einmal. Das ist Absicht der Sprache: Ein Argument mit Nebenwirkung gehört nicht in einen bedingten Aufruf, wenn du den Effekt brauchst.

</details>

## Caller-Info-Attribute

<Term id="caller-info-attribute">Caller-Info-Attribute</Term> (caller info attributes) stehen an optionalen Parametern. An der Aufrufstelle setzt der Compiler den Wert ein:

- `[CallerMemberName]`: Name der aufrufenden Methode
- `[CallerLineNumber]`: Zeilennummer des Aufrufs
- `[CallerFilePath]`: Pfad der Quelldatei (er ist maschinenabhängig, das Beispiel druckt ihn nicht)
- `[CallerArgumentExpression("parameter")]`: der Text des Ausdrucks, der für einen anderen Parameter übergeben wurde

## Achtung

:::warning[Achtung]
<Misconception id="m14-l06-attribute-runs-code" />

**„Ein Attribut führt beim Aufruf der Methode Code aus.“** Das stimmt nicht. Ein Attribut ist eine Information. Ein Objekt der Attributklasse entsteht erst, wenn ein Werkzeug das Attribut ausliest, nicht beim Aufruf der Methode.
:::

:::warning[Achtung]
<Misconception id="m14-l06-conditional-arguments-evaluated" />

**„Bei einem entfallenen bedingten Aufruf werden die Argumente trotzdem ausgewertet.“** Das stimmt nicht. Der Aufruf entfällt mit allen Argumenten.
:::

<details>
<summary>Vertiefung: Wann ein Attributobjekt entsteht (optional)</summary>

Der Compiler speichert Attributklasse, Konstruktor und Argumente in der Assembly. Ein Objekt der Attributklasse entsteht erst, wenn das Attribut zur Laufzeit abgefragt wird ([§23.4.2](https://learn.microsoft.com/dotnet/csharp/language-reference/language-specification/attributes#2342-compilation-of-an-attribute), [§23.4.3](https://learn.microsoft.com/dotnet/csharp/language-reference/language-specification/attributes#2343-run-time-retrieval-of-an-attribute-instance)). Ohne `[AttributeUsage]` gilt `AttributeTargets.All`, `AllowMultiple = false` und `Inherited = true` ([§23.2.2](https://learn.microsoft.com/dotnet/csharp/language-reference/language-specification/attributes#2322-attribute-usage)).

</details>

## Zusammenfassung

Ein Attribut ist eine Zusatzinformation in eckigen Klammern. Positionsparameter gehören zum Konstruktor, benannte Parameter setzen Eigenschaften. Das Attributziel ergibt sich aus der Stelle oder aus einem Präfix wie `return:` oder `assembly:`. `[Obsolete]` löst eine Warnung oder mit `error: true` einen Fehler aus, `[Conditional]` lässt Aufrufe samt Argumenten entfallen, Caller-Info-Attribute setzt der Compiler an der Aufrufstelle ein. Eine eigene Attributklasse erbt von `Attribute`, `[AttributeUsage]` legt Ziele und Mehrfachverwendung fest.
