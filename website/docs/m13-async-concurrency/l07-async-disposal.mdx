# Asynchrones Freigeben mit await using

:::note[Lernziele]
- Du kannst eine Klasse schreiben, die `IAsyncDisposable` mit `DisposeAsync` implementiert.
- Du kannst `await using` als Anweisung mit Block und als Deklaration verwenden.
- Du kannst vorhersagen, wann `DisposeAsync` aufgerufen wird, auch bei einer Ausnahme.
- Du kannst erklären, warum ein normales `using` bei einem Typ, der nur `IAsyncDisposable` hat, nicht passt.
:::

## Wenn das Freigeben warten muss

In Modul 7 hast du Ressourcen mit `using` und `Dispose` freigegeben. Manche Ressourcen müssen dabei noch Arbeit erledigen, die dauert: Sie schreiben restliche Daten weg oder beenden eine Verbindung. Eine solche Arbeit soll man mit `await` abwarten, statt einen Thread zu blockieren. `Dispose` kann das nicht, denn die Methode gibt nichts zurück, worauf man warten könnte.

Dafür gibt es die Schnittstelle <Term id="async-disposable">`IAsyncDisposable`</Term>. Sie hat eine Methode: `DisposeAsync` ohne Parameter. Die Methode gibt einen `ValueTask` zurück. Das ist eine leichtere Variante von `Task`, die du hier nur als Rückgabetyp brauchst. Ein Typ mit `IAsyncDisposable` wird mit <Term id="asynchronous-using">`await using`</Term> freigegeben. Die Anweisung ruft am Ende des Blocks `DisposeAsync` auf und wartet darauf ([§13.14.1 The using statement](https://learn.microsoft.com/dotnet/csharp/language-reference/language-specification/statements#13141-general)). Der Block ist wie bei `using` eine <Term id="using-statement">using-Anweisung</Term>, hier mit dem Zusatz `await`.

<CSharpRunner id="m13-l07-first" code={firstAsyncDispose} />

Die Methode `DisposeAsync` ist `async`, weil sie selbst wartet. `await using` darf nur dort stehen, wo `await` erlaubt ist, hier in den Anweisungen auf oberster Ebene.

## Auf jedem Weg aus dem Block

Wie bei `using` läuft die Freigabe auf jedem Weg aus dem Block: am normalen Ende, mit `return` und auch, wenn eine Ausnahme den Block verlässt. Der Compiler setzt dafür einen `finally`-Block ein.

:::info[Vorhersage]
Im Block wird eine Ausnahme ausgelöst, ein `catch` außerhalb fängt sie. In welcher Reihenfolge erscheinen die drei Zeilen?
:::

1. **Im Block arbeiten:** Das Programm gibt `Working` aus und löst die Ausnahme aus.
2. **Freigeben:** Beim Verlassen des Blocks läuft `DisposeAsync`. Es wartet kurz und gibt `Closed web` aus.
3. **Fangen:** Erst danach erreicht die Ausnahme den `catch` und `Caught: broken` erscheint.

## Als Deklaration und in umgekehrter Reihenfolge

Statt eines Blocks gibt es die <Term id="using-declaration">using-Deklaration</Term> auch mit `await`. Die Variable lebt dann bis zum Ende des umgebenden Blocks. Mehrere Ressourcen werden in umgekehrter Reihenfolge ihrer Deklaration freigegeben ([§13.14.2 Using declaration](https://learn.microsoft.com/dotnet/csharp/language-reference/language-specification/statements#13142-using-declaration)).

## using oder await using

Ein normales `using` verlangt `IDisposable` und ruft `Dispose` auf. Hat ein Typ nur `IAsyncDisposable`, passt es nicht. Der Compiler meldet einen Fehler und schlägt `await using` vor:

<CodeBlock language="csharp" title="plain-using-error.cs">{plainUsingError}</CodeBlock>

Der Compiler meldet in Zeile 1 den Fehler `CS8418`: „'Connection': type used in a using statement must implement 'System.IDisposable'. Did you mean 'await using' rather than 'using'?“

Ein Typ kann beide Schnittstellen haben. Dann entscheidet die Anweisung, welche Methode läuft ([Implement a DisposeAsync method](https://learn.microsoft.com/dotnet/standard/garbage-collection/implementing-disposeasync)).

## Projektschritt

**Stand bisher:** SecLog liest die Quellen zeilenweise als asynchrone Streams und zählt die Fehlversuche über alle Quellen.

Im Runner siehst du nur den Block `// Read the sources line by line as async streams`, das Ende des Programms, die Funktionen für das Laden und das Ende des Namensraums `SecLog.Model`. Der übrige Code ist ausgeblendet (Zeilen mit ⋯) und läuft beim Ausführen mit. Lass die Zeilen mit ⋯ stehen.

**Neue Anforderung:**

1. Schreibe in den Namensraum `SecLog.Model` hinter `ResolvedStatus` die Klasse `sealed class LogSourceReader : IAsyncDisposable`. Sie hat den Konstruktor `LogSourceReader(string name, string[] lines)`, die Eigenschaft `Name`, die Methode `int CountFailures()` (zählt die Zeilen mit `login-failed`) und `public async ValueTask DisposeAsync()`. `DisposeAsync` wartet mit `await Task.Delay(1)` und gibt `Reader closed: <Name>` aus.
2. Schreibe hinter den Block `// Read the sources line by line as async streams` und vor die Zeile `// End with exit code 0 …` den Block `// Release a log source reader asynchronously`. Er benutzt zuerst `await using (LogSourceReader reader = new("web", logSources["web"]))` und gibt im Block `Failures in web: <Anzahl>` aus. Danach folgt in einem eigenen Block `{ … }` ein Leser für `"vpn"` als `await using`-Deklaration. Er gibt `Failures in vpn: <Anzahl>` und `End of the block` aus. Nach dem Block gibt das Programm `After the blocks` aus.

## Achtung

:::warning[Achtung]
<Misconception id="m13-l07-using-calls-disposeasync" />

**„Ein normales `using` ruft auch `DisposeAsync` auf.“** Das stimmt nicht. Ein normales `using` verlangt `IDisposable` und ruft `Dispose` auf. Für einen Typ, der nur `IAsyncDisposable` hat, ist es ein Übersetzungsfehler. Nur `await using` ruft `DisposeAsync` auf und wartet darauf.
:::

<Quiz id="m13-l07-q2" />

## Zusammenfassung

Ein Typ, der beim Freigeben warten muss, implementiert `IAsyncDisposable` mit `public ValueTask DisposeAsync()`. `await using` ruft `DisposeAsync` am Ende des Blocks auf und wartet darauf, auch wenn der Block durch eine Ausnahme endet. Als Deklaration gilt die Freigabe bis zum Ende des umgebenden Blocks, mehrere Ressourcen werden in umgekehrter Reihenfolge freigegeben. Ein normales `using` ruft `Dispose` auf und passt nicht zu einem Typ, der nur `IAsyncDisposable` hat.
