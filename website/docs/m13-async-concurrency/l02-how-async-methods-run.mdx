## Die Reihenfolge der Schritte

Wer eine async-Methode aufruft, erwartet oft, dass der Aufruf ganz wartet und erst dann die nächste Zeile kommt. Das stimmt nur zum Teil. Das Programm zeigt, was wirklich passiert: Es nummeriert die Ausgaben in der Reihenfolge, in der sie im Code stehen.

:::info[Vorhersage]
In welcher Reihenfolge erscheinen die fünf Zeilen? Notiere die Nummern, bevor du das Programm startest.
:::

<CSharpRunner id="m13-l02-order" code={orderOfSteps} predict expected={orderOfStepsOutput} />

<details>
<summary>Lösung und Erklärung anzeigen</summary>

1. **Aufrufer bis zum Aufruf:** Zeile 1 erscheint, dann beginnt der Aufruf `LoadAsync()`.
2. **Methode bis zum ersten await:** Der Rumpf läuft ganz normal los und gibt Zeile 2 aus. Beim `await Task.Delay(10)` ist der Task noch nicht fertig.
3. **Rückkehr zum Aufrufer:** Die Methode gibt einen unfertigen `Task<int>` zurück. Der Aufrufer gibt Zeile 3 aus.
4. **Fortsetzung:** Erst am `await pending` wartet der Aufrufer. Wenn der Task fertig ist, läuft der Rest von `LoadAsync` (Zeile 4) und danach der Aufrufer (Zeile 5).

Was passiert, wenn du `await pending` vor die Ausgabe `3 after the call` schreibst? Dann erscheint Zeile 3 erst nach Zeile 4, weil der Aufrufer vorher wartet.

</details>

Das ist die Regel für jede async-Methode, die einen Task zurückgibt: Der Rumpf läuft synchron (Schritt für Schritt im Aufruf, ohne Pause) bis zum ersten `await` auf einen Task, der noch nicht fertig ist. Dort gibt die Methode einen unfertigen Task an ihren Aufrufer zurück. Den Rest der Methode führt später die <Term id="continuation">Continuation</Term> (Fortsetzung) aus, sobald der erwartete Task fertig ist ([§15.14.3 Evaluation of a task-returning async function](https://learn.microsoft.com/dotnet/csharp/language-reference/language-specification/classes#15143-evaluation-of-a-task-returning-async-function)).

## Ein fertiger Task macht keine Pause

Der erste Schritt der Regel sagt „unfertig“. Ist der Task beim `await` schon fertig, ist nichts zu erwarten, und die Methode läuft ohne Unterbrechung weiter. `Task.FromResult(1)` liefert so einen schon fertigen Task mit dem Wert `1`. Mit der Eigenschaft `IsCompleted` fragst du, ob ein Task fertig ist.

:::info[Vorhersage]
Welche drei Zeilen gibt das Programm aus?
:::

<CSharpRunner id="m13-l02-completed" code={completedOrPending} predict expected={completedOrPendingOutput} />

<details>
<summary>Lösung und Erklärung anzeigen</summary>

1. **Schon fertig:** `QuickAsync` wartet auf `Task.FromResult(1)`. Das `await` macht sofort weiter, die Methode läuft bis zum `return` durch. Der zurückgegebene Task ist fertig: `quick completed: True`.
2. **Noch nicht fertig:** `SlowAsync` wartet auf `Task.Delay(10)`. Direkt nach dem Aufruf läuft die Wartezeit noch, deshalb ist der Task unfertig: `slow completed: False`.
3. **Ergebnis:** Beide `await` im letzten Ausdruck liefern `1` und `2`. Die Summe ist `3`.

</details>

## Warum `await` den Thread nicht blockiert

Beim Warten auf einen unfertigen Task gibt die Methode ihre Kontrolle zurück (Schritt 3 im ersten Programm). Der Thread, der den Aufruf ausgeführt hat, steht dann nicht still, sondern führt die nächsten Zeilen des Aufrufers aus oder andere Arbeit. Erst wenn der Task fertig ist, wird der Rest der Methode fortgesetzt. Du siehst es am ersten Programm: Zeile 3 erscheint vor Zeile 4, obwohl die Methode in Zeile 2 noch „wartet“. Im Playground im Browser gibt es nur einen Thread, und die Reihenfolge ist trotzdem dieselbe.

## Die Rückgabetypen einer async-Methode

Der Rückgabetyp einer async-Methode ist `void`, ein <Term id="task-type">Task-Typ</Term> oder ein asynchroner Iteratortyp. Für den Anfang genügen zwei Task-Typen:

- `Task` für Arbeit ohne Ergebniswert (kein `return` mit Wert).
- `Task<T>` für Arbeit mit einem Ergebnis vom Typ `T` (`return` mit einem `T`).

Weitere Task-Typen wie `ValueTask` gibt es auch. Dieser Kurs nutzt sie nicht.

<Forward concepts={['`async void`']} module="13" />

`void` ist erlaubt, hat aber Nachteile. Wann du es meiden solltest, erklärt die Lektion „Stolperfallen bei async“.

## Achtung

:::warning[Achtung]
<Misconception id="m13-l02-await-blocks-thread" />

**„`await` blockiert den Thread, bis der Task fertig ist.“** Das stimmt nicht. Bei einem unfertigen Task gibt die Methode die Kontrolle an ihren Aufrufer zurück. Der Thread kann in der Zwischenzeit andere Arbeit erledigen. Im Browser mit nur einem Thread zeigt es sich daran, dass der Aufrufer seine Zeile vor dem Rest der Methode ausgibt.
:::

<details>
<summary>Vertiefung: Das Awaitable-Muster (optional)</summary>

`await` funktioniert nicht nur mit Tasks. Ein Ausdruck ist <Term id="awaitable">awaitable</Term> (erwartbar), wenn sein Typ eine Methode `GetAwaiter` ohne Parameter hat. Das Ergebnis, der Awaiter, setzt `INotifyCompletion` um, bietet die lesbare Eigenschaft `IsCompleted` und die Methode `GetResult` ([§12.9.9.2 Awaitable expressions](https://learn.microsoft.com/dotnet/csharp/language-reference/language-specification/expressions#12992-awaitable-expressions)). Zur Laufzeit holt `await` den Awaiter und liest `IsCompleted`. Ist der Wert `true`, geht es sofort mit `GetResult` weiter. Sonst meldet `await` die Fortsetzung beim Awaiter an und kehrt zum Aufrufer zurück ([§12.9.9.4 Run-time evaluation of await expressions](https://learn.microsoft.com/dotnet/csharp/language-reference/language-specification/expressions#12994-run-time-evaluation-of-await-expressions)). Das erklärt den fertigen Task aus dem zweiten Programm.

Der Compiler wandelt eine async-Methode normalerweise in eine Hilfsklasse um, die sich merkt, wo die Methode beim `await` stehen geblieben ist. Für den Code, den du schreibst, ändert sich nichts: Die Regeln dieser Lektion gelten unverändert.

## Zusammenfassung

Eine async-Methode läuft synchron bis zum ersten `await` auf einen unfertigen Task. Dann gibt sie einen unfertigen Task an ihren Aufrufer zurück, und der Rest läuft später als Fortsetzung. Ist der Task schon fertig, macht `await` ohne Pause weiter. Dabei blockiert `await` den Thread nicht. Eine async-Methode gibt `Task`, `Task<T>` oder (mit Nachteilen) `void` zurück oder einen asynchronen Iteratortyp. Erwartbar ist jeder Typ mit passender Methode `GetAwaiter`.
