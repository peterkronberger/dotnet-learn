## Was eine Variable enthält

In Modul 3 hast du gesehen: Ein Wertparameter bekommt eine Kopie des Arguments, und ein Tupel ist beim Kopieren unabhängig vom Original. Das gilt nicht für alle Typen. Es gibt zwei Arten von Typen, und sie unterscheiden sich darin, was eine Variable enthält.

Eine Variable eines <Term id="value-type">Value Type (Werttyp)</Term> enthält den Wert selbst. `int`, `double`, `bool`, `char` und Tupel sind Werttypen. Eine Zuweisung kopiert den Wert, danach sind beide Variablen unabhängig.

:::info[Vorhersage]
Was geben die beiden Zeilen aus?
:::

<CSharpRunner id="m04-l01-value-copy" code={valueCopy} predict expected={valueCopyOutput} />

<details>
<summary>Lösung und Erklärung anzeigen</summary>

Die Ausgabe ist `original: 5` und `copy: 7`.

1. **Wert kopieren:** `int copy = original;` legt eine Kopie der `5` in `copy`.
2. **Kopie ändern:** `copy = 7;` ändert nur `copy`.
3. **Original prüfen:** `original` enthält weiter die `5`.

**Was passiert, wenn du `original = 9;` vor der Ausgabe ergänzt?** Dann ist `original` `9` und `copy` weiter `7`. Die Variablen sind unabhängig.

</details>

## Variablen mit Verweis

Eine Variable eines <Term id="reference-type">Reference Type (Referenztyp)</Term> enthält nur einen Verweis (Referenz) auf ein <Term id="object">Object (Objekt)</Term>. Das Objekt selbst liegt an anderer Stelle. `new` erzeugt ein Objekt und liefert den Verweis darauf. Der Typ `string` ist ein Referenztyp, du kennst ihn aus Modul 1. Für dieses Modul brauchen wir einen Referenztyp, dessen Objekt sich ändern lässt: den <Term id="string-builder">StringBuilder</Term>. Er nimmt einen Text auf, an den du mit `Append` weiteren Text hängst. `ToString()` liefert den Text als `string`.

<Forward concepts={['Namespaces', '`using`-Direktive', 'Klassen', 'Konstruktoren']} module="6" />

Die erste Zeile `using System.Text;` macht den Typ `StringBuilder` unter seinem kurzen Namen bekannt. Die Textinterpolation `{first}` ruft `ToString()` auf und setzt den Text ein.

:::info[Vorhersage]
`second = first` weist eine Variable an die andere zu. Was zeigen die beiden Zeilen nach dem `Append`?
:::

<CSharpRunner id="m04-l01-reference-copy" code={referenceCopy} predict expected={referenceCopyOutput} />

<details>
<summary>Lösung und Erklärung anzeigen</summary>

Die Ausgabe ist zweimal `alice!`.

1. **Objekt erzeugen:** `new StringBuilder("alice")` erzeugt ein Objekt. `first` enthält den Verweis darauf.
2. **Verweis kopieren:** `var second = first;` kopiert den Verweis. Es gibt weiterhin nur ein Objekt, und beide Variablen zeigen darauf.
3. **Objekt ändern:** `second.Append("!")` hängt `!` an dieses eine Objekt. Über `first` ist die Änderung auch zu sehen.

**Was passiert, wenn du statt `var second = first;` ein zweites `new StringBuilder("alice")` schreibst?** Dann gibt es zwei Objekte. Die Änderung über `second` betrifft nur sein Objekt, und `first` bleibt `alice`.

</details>

:::warning[Achtung]
<Misconception id="m04-l01-assignment-copies-object" />

**„Eine Zuweisung kopiert das Objekt.“** Das stimmt nicht. Bei einem Referenztyp kopiert die Zuweisung nur den Verweis. Danach zeigen beide Variablen auf dasselbe Objekt, und eine Änderung über die eine Variable sieht man über die andere. Nur bei Werttypen wie `int` oder einem Tupel (Modul 3) kopiert die Zuweisung den Wert selbst.
:::

## `int` ist ein Alias

Das Schlüsselwort `int` ist ein anderer Name für die Struktur `System.Int32`. Man nennt solche Schlüsselwörter <Term id="simple-type">Simple Types (einfache Typen)</Term>. `double`, `bool` und `char` gehören dazu. Sie sind Werttypen. Eine Struktur ist eine Art von Werttyp. Eigene Typen schreibst du erst in späteren Modulen.

:::info[Vorhersage]
`Int32` und `int` sind derselbe Typ. Was gibt das Programm aus?
:::

<CSharpRunner id="m04-l01-alias" code={simpleTypeAlias} predict expected={simpleTypeAliasOutput} />

<details>
<summary>Lösung und Erklärung anzeigen</summary>

Die Ausgabe ist `5 6` und `2147483647`.

1. **Beide Namen nutzen:** `Int32 a = 5;` und `int b = a;` brauchen keine Umwandlung, denn es ist ein Typ.
2. **Kopie ändern:** `b++` ändert nur `b`, denn `Int32` ist ein Werttyp.
3. **Größten Wert lesen:** `int.MaxValue` ist eine Zahl vom Typ `int`. Sie passt in eine `Int32`-Variable.

**Was passiert, wenn du `Int32` durch `System.Int32` ersetzt?** Dasselbe: Es ist der volle Name des Typs.

</details>

Alle Typen stammen direkt oder indirekt von `object` ab. `object` ist die Wurzel. Darum kannst du bei jedem Wert `ToString()` aufrufen, auch bei einem `int`. Wie ein Werttyp als `object` behandelt wird, lernst du in der letzten Lektion dieses Moduls.

<details>
<summary>Vertiefung: Was die Spezifikation festlegt (optional)</summary>

Eine Variable eines Werttyps enthält ihre Daten direkt, eine Variable eines Referenztyps speichert einen Verweis auf ihr Objekt. Zwei Variablen können auf dasselbe Objekt zeigen, bei Werttypen hat jede Variable ihre eigene Kopie ([§8.1 Types: General](https://learn.microsoft.com/dotnet/csharp/language-reference/language-specification/types#81-general)).

Die einfachen Typen sind Aliase für vordefinierte Strukturen im Namespace `System` ([§8.3.5 Simple types](https://learn.microsoft.com/dotnet/csharp/language-reference/language-specification/types#835-simple-types)).

Jeder Typ stammt direkt oder indirekt von der Klasse `object` ab ([§8.2.3 The object type](https://learn.microsoft.com/dotnet/csharp/language-reference/language-specification/types#823-the-object-type)).
</details>

## Zusammenfassung

Eine Variable eines Werttyps enthält den Wert, und eine Zuweisung kopiert ihn. Eine Variable eines Referenztyps enthält einen Verweis auf ein Objekt, und eine Zuweisung kopiert den Verweis. Danach zeigen beide Variablen auf dasselbe Objekt. `int` ist ein anderer Name für den Werttyp `System.Int32`, und alle Typen stammen von `object` ab. Der `StringBuilder` ist der veränderbare Referenztyp dieses Moduls.
