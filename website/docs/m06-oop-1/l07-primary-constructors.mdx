# Primärkonstruktoren

:::note[Lernziele]
- Du kannst eine Klasse mit Primärkonstruktor deklarieren und seine Parameter in Membern verwenden.
- Du kannst erklären, warum ein Parameter des Primärkonstruktors keine Eigenschaft ist.
- Du kannst einen weiteren Konstruktor mit `this(…)` an den Primärkonstruktor binden.
:::

## Die Parameterliste hinter dem Klassennamen

<Since csharp="12" dotnet="8" />

Ein Konstruktor aus Lektion 2 braucht meist drei Dinge: ein Feld, einen Parameter und eine Zuweisung `this.title = title;`. Ein <Term id="primary-constructor">Primärkonstruktor</Term> (Primary Constructor) kürzt das ab. Du schreibst die Parameterliste direkt hinter den Klassennamen: `class Alert(string title, int level)`. Die Parameter gelten im ganzen Klassenrumpf, also in Methoden, Eigenschaften und Initialisierern ([Primary constructors](https://learn.microsoft.com/en-us/dotnet/csharp/whats-new/tutorials/primary-constructors)).

Benutzt ein Member einen Parameter, erfasst der Compiler ihn (<Term id="capture">Capture</Term>): Er legt dafür im Objekt einen versteckten Speicher an und schreibt den Wert beim Erzeugen hinein. So ist der Wert auch noch da, wenn die Methode später läuft. Ein Feld und eine Zuweisung brauchst du nicht zu schreiben.

:::info[Vorhersage]
Was gibt das Programm aus? Die Methode `Describe` benutzt die beiden Parameter der Kopfzeile.
:::

<CSharpRunner id="m06-l07-basic" code={primaryBasic} predict expected={primaryBasicOutput} />

<details>
<summary>Lösung und Erklärung anzeigen</summary>

Die Ausgabe ist `Many failed logins: level 3` und `Disk full: level 1`.

1. **Aufruf:** `new Alert("Many failed logins", 3)` ruft den Primärkonstruktor auf. Die Werte kommen in die Parameter `title` und `level`.
2. **Erfassen:** `Describe` liest beide Parameter. Der Compiler speichert deshalb die Werte im Objekt.
3. **Eigene Werte:** Jedes Objekt hat seine eigenen Werte, wie bei Feldern.

Was passiert, wenn `Describe` den Parameter `level` nicht benutzt? Dann speichert der Compiler `level` nicht. Das Programm läuft trotzdem.

</details>

## Ein Parameter ist keine Eigenschaft

Ein Parameter des Primärkonstruktors ist kein Member der Klasse. Er ist nur ein Name, der im Klassenrumpf gilt. Von außen führt kein Weg zu ihm: `alert.title` übersetzt nicht ([Primary constructors](https://github.com/dotnet/csharplang/blob/main/proposals/csharp-12.0/primary-constructors.md)).

<CodeBlock language="csharp" title="primary-outside.snippet.cs">{primaryOutside}</CodeBlock>

Die zweite Zeile ist der Fehler. Der Compiler meldet, dass `Alert` keine Definition für `title` enthält (CS1061).

Willst du den Wert zeigen, deklarierst du selbst eine Eigenschaft. Ein Parameter kann außerdem eine Eigenschaft oder ein Feld initialisieren, zum Beispiel `public int Level { get; } = level;`.

<CSharpRunner id="m06-l07-property" code={primaryProperty} />

Die Ausgabe ist `Many failed logins / 3` und `Many failed logins: level 3`.

- `Title => title` ist eine Eigenschaft ohne Speicher von uns. Sie liest den erfassten Parameter.
- `Level { get; } = level` kopiert den Wert beim Erzeugen in das Hintergrundfeld der Eigenschaft. Der Parameter `level` wird nur dort gelesen, also erfasst der Compiler ihn nicht.

Records machen aus Parametern der Kopfzeile automatisch Eigenschaften. Bei einer Klasse tust du das selbst.

<Forward concepts={['Records']} module="8" />

## Weitere Konstruktoren

Eine Klasse mit Primärkonstruktor darf weitere Konstruktoren haben. Jeder von ihnen muss mit `: this(…)` den Primärkonstruktor aufrufen, direkt oder über einen anderen Konstruktor. Sonst bekämen die Parameter keinen Wert. Die Verkettung kennst du aus Lektion 2 (<Term id="constructor-chaining">Konstruktorverkettung</Term>).

:::info[Vorhersage]
Was gibt das Programm aus, und in welcher Reihenfolge? Der zweite Konstruktor hat nur einen Parameter.
:::

<CSharpRunner id="m06-l07-chain" code={primaryChain} predict expected={primaryChainOutput} />

<details>
<summary>Lösung und Erklärung anzeigen</summary>

Die Ausgabe ist `one parameter: Disk full`, danach `Many failed logins: level 3` und `Disk full: level 1`.

1. **Erster Aufruf:** `new Alert("Many failed logins", 3)` nutzt den Primärkonstruktor. Er druckt nichts.
2. **Zweiter Aufruf:** `new Alert("Disk full")` ruft `this(title, 1)` auf. Der Primärkonstruktor läuft zuerst, danach der Körper mit `Console.WriteLine`.
3. **Reihenfolge:** Beide `new`-Zeilen laufen vor den `Describe`-Aufrufen. Deshalb steht die Zeile des Konstruktors oben.

Was passiert, wenn du `: this(title, 1)` weglässt? Der Compiler lehnt den Konstruktor ab.

</details>

## Lückenbeispiel

Die Klasse `Alert` hat zwei Felder und einen Konstruktor, der sie setzt. Forme sie in eine Klasse mit Primärkonstruktor um. Die Ausgabe `Disk full: level 2` soll gleich bleiben. Tipp: Die Felder und der Konstruktor entfallen, der Parameter `title` steht in der Kopfzeile.

<CSharpRunner id="m06-l07-gaps" code={primaryGap} />

<details>

1. **Kopfzeile:** `class Alert(string title, int level)`.
2. **Entfernen:** Die beiden Felder und der Konstruktor entfallen.
3. **Behalten:** `Describe` bleibt unverändert, weil `title` und `level` jetzt Parameter sind.

## Achtung

:::warning[Achtung]
<Misconception id="m06-l07-primary-parameter-is-property" />

**„Ein Parameter des Primärkonstruktors ist eine Eigenschaft.“** Das stimmt nicht. Der Parameter gilt nur im Klassenrumpf. Von außen gibt es kein Member mit diesem Namen. Eine Eigenschaft musst du selbst deklarieren, zum Beispiel `public string User => user;`.
:::

## Zusammenfassung

Ein Primärkonstruktor steht als Parameterliste hinter dem Klassennamen. Seine Parameter gelten im ganzen Klassenrumpf. Benutzt ein Member einen Parameter, erfasst der Compiler ihn und speichert den Wert im Objekt. Die Parameter sind keine Member, deshalb ist `obj.user` von außen nicht möglich. Eine Eigenschaft wie `User => user` gibt den Wert weiter. Jeder weitere Konstruktor ruft mit `this(…)` den Primärkonstruktor auf.
