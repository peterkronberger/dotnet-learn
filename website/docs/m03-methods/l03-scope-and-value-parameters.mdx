# Gültigkeitsbereich und Wertparameter

:::note[Lernziele]
- Du kannst bestimmen, wo ein Name gültig ist (Block, Methode).
- Du kannst erklären, warum zwei Methoden denselben Variablennamen benutzen dürfen.
- Du kannst vorhersagen, dass eine Zuweisung an einen Wertparameter die Variable des Aufrufers nicht ändert.
- Du kannst erkennen, dass eine Methode in einem Programm mit Top-Level-Anweisungen Variablen außerhalb sehen kann, und erklären, warum Parameter klarer sind.
:::

## Wo gilt ein Name?

Der <Term id="scope">Gültigkeitsbereich (Scope)</Term> eines Namens ist der Teil des Programmtexts, in dem du ihn benutzen kannst. Eine <Term id="local-variable">lokale Variable (Local Variable)</Term> gilt ab ihrer Deklaration bis zur schließenden Klammer des Blocks, in dem sie steht. Ein Parameter gilt im Rumpf seiner Methode und ist dort wie eine lokale Variable.

Außerhalb ihres Bereichs ist der Name unbekannt. Im Fragment unten wird `doubled` im Block der Schleife deklariert und danach außerhalb benutzt. Das lässt der Compiler nicht zu.

<CodeBlock language="csharp" title="scope-block-error.snippet.cs">{scopeError}</CodeBlock>

Wo ein Name nur einmal vorkommen darf, hängt vom <Term id="declaration-space">Deklarationsraum (Declaration Space)</Term> ab. Der Rumpf einer Methode ist ein eigener Raum. Zwei Methoden, die sich nicht umschließen, haben getrennte Räume. Darum darf derselbe Name in beiden stehen.

:::info[Vorhersage]
Beide Methoden deklarieren eine Variable `result`. Läuft das Programm, und welche Werte gibt es aus?
:::

<CSharpRunner id="m03-l03-names" code={sameName} predict expected={sameNameOutput} />

<details>
<summary>Lösung und Erklärung anzeigen</summary>

Die Ausgabe ist `5` und `6`.

1. **Getrennte Räume:** `result` in `Sum` und `result` in `Product` sind zwei verschiedene Variablen. Keine kennt die andere.
2. **Eigene Parameter:** Auch `a` und `b` sind zweimal da, jeweils nur in ihrer Methode gültig.
3. **Werte:** `Sum(2, 3)` liefert `5`, `Product(2, 3)` liefert `6`.

**Was passiert, wenn du in einer Methode zweimal `int result` deklarierst?** Dann stehen zwei gleiche Namen im selben Raum, und der Compiler meldet einen Fehler.

</details>

## Wertparameter sind Kopien

Ein Parameter ohne besonderen Zusatz heißt <Term id="value-parameter">Wertparameter (Value Parameter)</Term>. Er ist eine neue lokale Variable, die beim Aufruf eine Kopie des Arguments bekommt. Die Methode darf ihm neue Werte zuweisen. Das ändert nur die Kopie, nicht die Variable, die der Aufrufer als Argument übergeben hat.

:::info[Vorhersage]
`failures` ist `3`. Welche Werte gibt das Programm in den drei Zeilen aus?
:::

<CSharpRunner id="m03-l03-value" code={valueParameter} predict expected={valueParameterOutput} />

<details>
<summary>Lösung und Erklärung anzeigen</summary>

Die Ausgabe ist `Inside AddOne: 4`, `After the call: 3` und `After the assignment: 4`.

1. **Kopie anlegen:** Beim Aufruf `AddOne(failures)` entsteht `number` mit dem Wert `3`.
2. **Kopie ändern:** `number = number + 1` ändert nur `number` auf `4`.
3. **Aufrufer prüfen:** `failures` ist weiter `3`.
4. **Wert zurückgeben:** Soll der Aufrufer etwas Neues bekommen, liefert die Methode es mit `return`. Dann weist `failures = AddedOne(failures)` es der Variablen zu.

**Was passiert, wenn der Aufrufer den Rückgabewert nicht zuweist?** Dann geht der neue Wert verloren. `failures` bleibt `3`.

</details>

:::warning[Achtung]
<Misconception id="m03-l03-method-changes-caller-variable" />

**„Eine Methode ändert die Variable des Aufrufers, wenn sie ihrem Parameter etwas zuweist.“** Der Parameter ist eine Kopie. Die Zuweisung wirkt nur in der Methode. Für einen neuen Wert beim Aufrufer brauchst du `return` und eine Zuweisung im Aufrufer.
:::

Die Beispiele hier benutzen Zahlen, Wahrheitswerte und Texte als Argumente. Wie sich Werte mit Verweis verhalten, folgt in Modul 4.

## Lückenbeispiel

Die Methode `Reset` soll `attempts` auf `0` setzen, aber die Ausgabe ist `5`. Ändere das Programm so, dass es `0` ausgibt. Nutze dazu `return` und eine Zuweisung im Aufrufer.

<CSharpRunner id="m03-l03-gaps" code={resetGaps} />

<details>
<summary>Lösung anzeigen</summary>

1. **Wert zurückgeben:** `int Reset(int value) { return 0; }`
2. **Zuweisen:** `attempts = Reset(attempts);`

Der Parameter `value` bekommt nur eine Kopie. Erst die Zuweisung im Aufrufer bringt den neuen Wert in `attempts`.

</details>

## Zusammenfassung

Ein Name gilt vom Ort seiner Deklaration bis zum Ende seines Blocks, ein Parameter im Rumpf seiner Methode. Getrennte Methoden haben getrennte Deklarationsräume und dürfen dieselben Namen benutzen. Ein Wertparameter ist eine Kopie des Arguments, eine Zuweisung daran ändert die Variable des Aufrufers nicht. Einen neuen Wert bekommt der Aufrufer über `return`. Parameter machen sichtbar, was eine Methode braucht.
