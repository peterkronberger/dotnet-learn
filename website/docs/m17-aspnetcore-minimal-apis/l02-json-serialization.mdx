## JSON: Daten als Text

Eine HTTP-Antwort aus Lektion 1 hatte einen Body mit Text wie `{"id":1,"status":"open"}`. Dieses Format heißt <Term id="json">JSON</Term>. Es kennt sieben Arten von Werten:

- **Objekt:** Paare aus Name und Wert in `{ }`, getrennt durch Kommas. Der Name steht in doppelten Anführungszeichen, ein Doppelpunkt trennt ihn vom Wert.
- **Array:** eine Liste von Werten in `[ ]`.
- **String:** Text in doppelten Anführungszeichen.
- **Zahl:** `7` oder `2.5`.
- **`true` und `false`.**
- **`null`:** kein Wert.

Das Programm liest einen JSON-Text mit allen Arten und gibt zu jedem Namen die Art des Wertes aus. Dazu nutzt es `JsonDocument`: Es zerlegt einen JSON-Text, ohne dass du einen C#-Typ dafür brauchst. `ValueKind` nennt die Art eines Wertes.

:::

## Objekte in JSON umwandeln und zurück

Die Aufgabe, ein Objekt in Text zu verwandeln, den man speichern oder senden kann, heißt <Term id="serialization">Serialisierung</Term>. Die Gegenrichtung, aus Text wieder ein Objekt zu bauen, heißt <Term id="deserialization">Deserialisierung</Term>. `JsonSerializer` im Namensraum `System.Text.Json` kann beides:

- `JsonSerializer.Serialize(objekt)` liefert den JSON-Text.
- `JsonSerializer.Deserialize<T>(text)` liefert ein Objekt vom Typ `T`. Das Ergebnis kann `null` sein, wenn der Text `null` ist. Darum hat der Rückgabetyp ein `?`.

Der Serializer schreibt die öffentlichen Eigenschaften. Ein Record (Modul 8) ist dafür eine gute Form: Seine Eigenschaften stehen in einer Zeile. Ein positionaler Record wird über seinen Konstruktor gefüllt, der Serializer findet ihn selbst.

## Optionen: Namen und Einrückung

Im ersten Lauf stimmten die JSON-Namen mit den C#-Namen überein, mit großem Anfangsbuchstaben. Das ist die Voreinstellung. Webschnittstellen schreiben Namen meist in camelCase: erster Buchstabe klein, spätere Wörter groß, also `failureCount`. Mit `JsonSerializerOptions` änderst du das. Eine <Term id="naming-policy">Namensrichtlinie</Term> wandelt alle C#-Namen um: `PropertyNamingPolicy = JsonNamingPolicy.CamelCase`.

Die Optionen `JsonSerializerDefaults.Web` setzen die Einstellungen, die ASP.NET Core für Web-Anwendungen verwendet: camelCase beim Schreiben, Groß- und Kleinschreibung der Namen ist beim Lesen egal, und Zahlen dürfen auch als Text im JSON stehen. Du übergibst sie dem Konstruktor und setzt weitere Optionen in geschweiften Klammern dahinter, zum Beispiel `WriteIndented = true` für eingerückte Ausgabe. <Since dotnet="9" /> Das Singleton `JsonSerializerOptions.Web` liefert diese Einstellungen fertig ([Instantiate JsonSerializerOptions](https://learn.microsoft.com/dotnet/standard/serialization/system-text-json/configure-options)).

Ein einzelner Name lässt sich mit dem Attribut `[JsonPropertyName("…")]` festlegen (Attribute, Modul 14). Er gilt in beide Richtungen und hat Vorrang vor der Namensrichtlinie. Bei einem positionalen Record sitzt das Attribut mit dem Ziel `property:` am Parameter, damit es an der Eigenschaft landet.

## Fehlende und null-Werte

Beim Einlesen setzt der Serializer nur, was im JSON steht. Fehlt ein Name, bleibt die Eigenschaft beim Startwert, den der Typ ihr gibt: 0, `null` oder ein eigener Initialisierer wie `"unknown"`. Steht `null` im JSON, setzt der Serializer `null`. Das gilt auch für ein `string` ohne `?`: Die Nullbarkeit von Referenztypen prüft der Compiler, zur Laufzeit gibt es sie nicht.

<Since dotnet="9" /> Wer das nicht möchte, schaltet `RespectNullableAnnotations = true` ein. Dann löst ein `null` im JSON für eine nicht nullable Eigenschaft eine `JsonException` aus. Ein fehlender Name löst auch dann keine aus ([Respect nullable annotations](https://learn.microsoft.com/dotnet/standard/serialization/system-text-json/nullable-annotations)). Eine Pflicht für das Vorhandensein erzwingt das Schlüsselwort `required` (Modul 6): Fehlt die Eigenschaft im JSON, gibt es eine `JsonException` ([Require properties](https://learn.microsoft.com/dotnet/standard/serialization/system-text-json/required-properties)). Dasselbe für Konstruktorparameter erreicht <Since dotnet="9" /> `RespectRequiredConstructorParameters`. Text, der gar kein JSON ist, löst ebenfalls eine `JsonException` aus. Wie jede Ausnahme (Modul 7) fängst du sie mit `try`/`catch`.

## Achtung

:::warning[Achtung]
<Misconception id="m17-l02-json-names-match-csharp" />

**„JSON-Namen sind immer genau die C#-Eigenschaftsnamen.“** Das gilt nur für die Voreinstellung. Eine Namensrichtlinie (die Web-Einstellungen nutzen camelCase) oder `[JsonPropertyName]` ändert die Namen. Beim Einlesen müssen die Namen dann zu dieser Regel passen.
:::

:::warning[Achtung]
<Misconception id="m17-l02-nullable-checked-on-read" />

**„Ein `string` ohne `?` garantiert beim Einlesen, dass der Wert nicht `null` ist.“** Ohne `RespectNullableAnnotations` prüft der Serializer die Nullbarkeit nicht. Ein `null` im JSON ergibt `null` in der Eigenschaft. Auch mit der Option bleibt ein fehlender Name erlaubt. Ein Pflichtfeld erzwingst du mit `required`.
:::

<details>
<summary>Vertiefung: Quellgenerator und Native AOT (optional)</summary>

Die Beispiele dieser Lektion nutzen Reflexion: Der Serializer liest die Form der Typen zur Laufzeit. Als Alternative erzeugt ein Quellgenerator diese Informationen beim Übersetzen. Das spart Speicher und Start und ist für Native AOT und Trimming nötig. Dabei nimmst du eine von `JsonSerializerContext` abgeleitete Klasse. Die Lektion nennt den Weg nur. Einzelheiten stehen bei [Reflection versus source generation](https://learn.microsoft.com/dotnet/standard/serialization/system-text-json/reflection-vs-source-generation).

</details>

## Zusammenfassung

JSON ist ein Textformat aus Objekten, Arrays, Strings, Zahlen, `true`/`false` und `null`. `JsonSerializer.Serialize` macht aus einem Objekt Text, `Deserialize<T>` liest es zurück. Optionen bestimmen die Namen: `JsonSerializerDefaults.Web` schreibt camelCase und liest ohne Beachtung der Schreibweise, `[JsonPropertyName]` setzt einen Namen fest. Fehlende Namen lassen den Startwert stehen, `null` wird übernommen. `required` und `RespectNullableAnnotations` verschärfen das, ungültiger Text löst eine `JsonException` aus.
